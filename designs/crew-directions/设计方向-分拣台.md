## 一、操作者终于说清的那句话

> 「我是想什么杂七杂八任务都丢进来的那种感觉，然后大哥开始帮我一件件去分配去安排。」

拆开是两个动作：

1. **丢** —— 什么都能扔，不分类、不等回复、不管大小
2. **分** —— 大哥接住，一件件拆开、派给谁、排好队、办掉

**主视觉是「安排」这件事，不是「对话」。** 回话只是副产品。

---

## 二、前五轮为什么全错

我一直把**聊天记录**当主视觉：

| 轮次 | 主视觉 | 错在哪 |
|---|---|---|
| 1–3 | 三栏里的消息气泡流 | 默认了「这是聊天应用」 |
| 4 | 冷白 / 极深 / 纸感三方向 | 只是给聊天窗口换皮 |
| 5 | 桌面工牌 + 记录簿 | 把对话做成一页静态日志，被问「平时聊天的面板呢」 |
| 6 | 记录簿 = 可滚动聊天面板 | **还是聊天**，只是纸做的 |

**证据其实一直在真机截图里**：用户连着丢了「今天天气怎么样」「在桌面写个 ok.txt 内容是 done」「以后都先说结论」「现在几点了」四件完全不同的事，中间基本没等回复。这不是对话，是**往筐里扔东西**。我把它读成了聊天。

仓库自己的域模型也早写了：`docs/01-architecture.md` 的 `Gate → Eval → Mandate → Ticket → Assignment → Outbox`，README 第一句「后台只留一本账」。**该上主界面的是这本账，不是消息时间线。**

## 三、主隐喻：案头 / 分拣台

材质沿用上一版（操作者说「有点感觉了」的是纸感，不是内容）：亚麻布底、纸条、朱红墨、衬线、印章、轻微旋转与叠压。**换掉的是内容主体。**

一条从左到右的流水线，不是三栏等分：

| 段 | 是什么 | 视觉 |
|---|---|---|
| **收件筐** | 什么都往这儿丢 | 7 张大小不一、宽窄不同、旋转各异的纸条：长句、带文件名的、定规矩的、链接、语音条、等你拍板的、刚丢进来还没分的。顶部一个虚线投递口 |
| **大哥在分** | 安排这件事可见 | 大哥小工牌 + 一句「收到 7 件，我按人分一下」；下面几张纸条被贴上**手写箭头标签**「→ 码农」「→ 写手」「我自己记」「等你拍板」；虚线连线从筐经分拣带指向各人堆 |
| **各人的活儿** | 分完之后的秩序 | 三小堆（大哥 / 写手 / 码农），每堆按顺序叠纸条；**正在跑的那张抬起来**、有进度和时长；办完的滑到底下盖「办」章 |

底部一条计数带：`收进 7 · 已分 5 · 待分 1 · 等你拍板 1 · 在跑 1 · 办完 3`。

**「安排」的可见性靠四样东西**：连线、手写派单标签、被抬起的在跑纸条、底部计数变化。不是靠文字解释 —— 上一轮已经被嫌过「解释太多」。

## 四、为什么这个方向站得住

1. **对上域模型** —— Ticket 是唯一状态主体，`Assignment` 就是「派给谁」。画板上的箭头标签就是 Assignment 的具象
2. **对上 24 条路由** —— `send`（丢一件）、`withdraw`（还没分可以拿回）、`steer`（插一句改变安排）、`takeover`（这件我自己来）、`retry`、`pause`、`routines`（定时往筐里丢）。这些路由本来就是为这个流设计的，只是界面一直按聊天画
3. **对上真实用法** —— 真机里连续丢四件事的行为，只有收件筐解释得通
4. **「杂七杂八」是特性** —— 异构输入（话 / 链接 / 图 / 语音 / 文件）本来就长得不一样，纸条不整齐反而是对的。前面几轮把它强行排成统一列表，恰恰抹掉了这个感觉
5. **不是普遍皮肤** —— 分拣台 / 案头隐喻在 AI 产品里几乎没人做；且它从产品内核长出来，不是从 Linear / Vercel 借来的

## 五、手机：把「丢一件」放到最显眼

`Desk-triage-mobile`（390×844）不是缩小桌面：

- 顶部是大哥一句「收到 7 件，我按人分一下」
- **紧接着一个 58px 的虚线大按钮「＋ 丢一件进来（话 / 链接 / 图 / 语音）」** —— 用户要的「丢」必须是第一动作
- 下面按状态分组的纸条流：还没分 → 等你拍板（带两个真按钮）→ 各人在跑（带进度）→ 办完了（盖章）
- 底部固定一条「丢 →」输入行

分工：桌面看**全局的分派**，手机管**随手丢一件 + 该我拍板的那件**。

## 六、落地

`mygo v0.8.3` 里现有、项目没用的 API 正好够：`Rotate`（纸条歪斜）、`Shadow`（叠压）、`Translate/Scale`（被抬起的在跑纸条）、`AnimateTo` + `ui.Snappy`（丢进来时纸条落进筐、分派时滑向某堆）、`CubicBezier`（共用曲线）、`Preferences.ReduceMotion`。Compose 侧 `graphicsLayer` + `AnimatedVisibility`。

**动效在这个方向里第一次有了叙事作用**：不是装饰性的 hover，是「一件东西从筐里被拿起 → 贴上派单标签 → 滑进某人的堆」。上一轮的 spring 规范全部沿用，但终于用对了地方。

契约层不用改：24 条路由、`empty`/`unavailable` 语义、`ticket_ref` 只读展示、反编造规则全部保留。

## 七、风险

1. **纸条多了会乱** —— 需要「同状态叠成一摞 + 只露最上一张 + 计数」的规则，不能无限摊开
2. **异构输入的呈现** —— 链接 / 图片 / 语音条的缩略形态要单独定，别都退化成一行字
3. **自动分派的置信度** —— 大哥派错了要能一键改派（`POST /api/mobile/bots` 已有写能力，`steer` 可复用），别做成黑箱
4. **「等你拍板」不能被埋** —— 真机截图里这条最重要，视觉权重要高于普通纸条
5. **衬线中文字体要引文件**（沿用上一版风险）
6. **信息密度** —— 比聊天窗口高，手机端要严格分组，不能一屏糊到底

## 九、两种模式：同一本账，换镜头

操作者补了一句「还是要有一个聊天模式」，随后又定调：**「日常聊天不需要太花哨，有点回到现在这种感觉，有一个事务板在旁边然后左侧正常聊，有点 QQ 群聊那种」**。

所以两个模式的视觉语言**不一样，这是场景差异不是不一致**：

| | 分拣台 | 聊天模式 |
|---|---|---|
| 什么时候用 | 想看全局安排：收进什么、派给谁、卡在哪 | 日常说话、随口问一句、跟某一位来回 |
| 视觉 | 纸感案头（亚麻/纸条/朱红/衬线） | **常规暗色界面，回到现有实现的感觉** |
| 主区 | 一条从收件筐到各人堆的流水线 | **左侧正常群聊**：头像 + 名字 + 气泡 + 系统提示 + 底部输入 |
| 旁边 | 各人的活儿堆就是主体 | **右侧一块事务板**（紧凑列表，不是纸条） |

### 聊天模式长什么样

- **顶栏**：群名「我的队伍 · 3 位在线」+ 一个普通 segmented「聊天 / 分拣台」。**不要纸质翻牌、不要衬线、不要印章** —— 那些是分拣台的语言，日常聊天用不上
- **成员条**：一排 chips（大哥高亮带在跑点 / 写手 / 码农），QQ 群那种「谁在群里」的感觉
- **左侧群聊**：自己的话靠右深色气泡、Bot 的话左对齐带头像和署名、连续同一人可省名字；系统提示居中小灰条「大哥把『写个 ok.txt』派给了码农」；「等你决定」卡直接插在消息流里；底部 `@` + 输入框 + 发送
- **右侧事务板**：就是分拣台的紧凑列表版，分组相同 —— 待分 / 在跑（带进度）/ 等你拍板 / 办完。每条一个状态点 + 标题 + 谁 + 时间，点一条跳回群里那句话
- **手机**：顶部「事务板」按钮带未读数，点开从右滑入抽屉；聊天本身仍是常规消息流 + 底部输入

配色用现有暗色体系：`#17161A` 底 / `#1D1C21` 栏 / `#232228` 卡 / `#33313A` 线 / `#F2EFEA` 字 / `#5FBFA8` 强调 / `#E0A574` 等你拍板。**不加新色系。**

### 契约依据（别做成两套状态）

`docs/00-contract.md` §1 写死：Ticket 是唯一状态主体，`ticket_id` 只是给前台展示的**只读引用**，前台不得据此维护自己的任务账。`GET /timeline` 一次就返回 `items`（消息）+ `tasks`（工单）+ `queued` + `declined`。

所以切换只改渲染顺序与分组，**不新建状态、不重新拉账**。事务板里的每一条就是 `tasks[]` 里的一项，群聊里的系统提示就是同一件事在 `items[]` 里的呈现。

### 两个模式之间的桥

1. **聊天 → 事务板**：消息被识别成任务时，群里出现系统提示，事务板同步多一条。标记「已进筐 / 已记住」只读展示，**只认后端给的 `ticket_ref`，不许客户端按时间或关键词猜**（契约反复强调「对不上时宁可不画」）
2. **事务板 → 聊天**：点任一条跳回群里对应的那句话；反过来 `ticket_ref` 已由后端给每条对得上票的回话补上了，不用新造接口
3. **分拣台 ↔ 聊天**：顶栏 segmented 直接切，不经过第三层页面

### 和谁聊

成员 chips 里点谁就是 @ 谁；没人点时大哥接话。**完全复用 `00-contract.md` §3 的确定性路由**，不新造选人逻辑。

### 新增风险

1. **别把聊天做成纸感** —— 记录簿、衬线、印章、翻牌都属于分拣台；聊天模式越普通越好，用户明确要「QQ 群聊那种」
2. **模式切换不能丢滚动位置** —— 从聊天翻回分拣台再翻回来，应回到原来那条消息
3. **事务板别抢主区** —— 它是「在旁边」的板，桌面约 500px、手机是抽屉，不能变成第三个主界面
4. **两个模式的输入语义不同** —— 分拣台「丢 →」（什么都能扔），聊天「说一句 →」（对某人说）。别共用一个占位文案
5. **别把聊天做成主模式** —— 分拣台是定案主视觉，聊天是日常使用面；默认落哪个由用户习惯决定，规则上不写死

## 十、一次复盘

从「太素」到这一版，中间换了六次方向。真正的问题**从来不是皮肤，是信息架构**：现有实现的骨架（暗色、群聊、右侧栏）本来是对的，我把它当成「普遍」一路换掉，绕了一圈才发现该留的是它，**该补的只是右侧那块板上装的是「事务」而不是设备列表 / 产出 / 记忆的杂项**。

保留这条，免得下一轮又去改配色。

## 十一、实施口径（2026-11-13 开始改代码）

两个模式已定案，开始落 `desktop/`（Go + mygo）与 `app/`（Kotlin + Compose）。**后端一行不改** —— `GET /timeline` 已返回 `items` / `tasks` / `queued` / `declined`，事务板的数据源全部现成。

### 数据映射（核实过 `backend/src/app/mobile-http.ts:888-934`）

| 界面分组 | 数据来源 | 判定 |
|---|---|---|
| 还没回的话（=「待分」） | `queued` 的 request_id → 反查 `items` 里 `role=user` 的消息文本 | **不是任务集**。`queuedRequests()` :1021 带 90 秒窗口，语义是「已接受、还没回复、还能撤回」。反查不到就跳过，不编条目，标题如实写「还没回的话」 |
| 在跑 | `tasks[]` | `open && needs_person` 为空 |
| 等你拍板 | `tasks[]` | `open && needs_person` 非空。`question` / `options` 可能为空 —— 空就只显示原因，**不画 A/B 按钮**（契约 §5 禁止编选项） |
| 办完 | `tasks[]` | `!open` |
| 进度条 | `total_steps` / `steps_done` | 只在 `total_steps > 0` 时画，比例夹在 `[0,1]`，与 `desktop/ui.go:4004 progressOf`、`CrewUi.kt:2128 TaskRow` 同口径。没有计划就不画 |
| `declined` | 后台看过决定不动手的消息 | 这一轮不进事务板 |

- 顶栏普通 segmented「聊天 / 分拣台」，不用翻牌
- 桌面右栏新增 `navBoard`（事务板）并设为默认页签；手机是顶部按钮 + 右侧抽屉

### 真机验收后的两处修复（2026-11-13 02:50）

手机插着真机跑过之后修掉两条：

1. **孤立的「听」字** —— `CrewWire.SpeechCopy.LISTEN` 原为单字「听」，逐条挂在 Bot 消息下面看着像渲染坏了。改成「听播报」，真机截图确认。
2. **手机分拣台材质** —— 新增 `TriagePalette`（`LightPalette.copy(...)`，与桌面 `desktop/triage.go` 同一套亚麻/纸条/墨/朱红值），分拣台整屏含顶栏都用它；**聊天模式与事务板抽屉仍是暗色**。所有前景色按 WCAG 实算过（最低 4.89:1，全部 ≥ 4.5）。`warn` 从 `#96603A` 调到 `#8A552F`，因为它在亚麻底上只有 4.35:1。

**剩余项**：分拣台目前是三段骨架，画板级纸条旋转 / 连线 / 动效未做（需要桌面窗口验收，本轮不抢焦点）；这台 OPPO 的系统字体把中文渲染成书法体，app 只用 `FontFamily.Default`，是系统替换不是 bug，要统一得自带字体文件；顶部仍保留旧结构（「我的队伍」+ 花名册横排 + 屏幕/模型/后台），符合「回到现在这种感觉」的定调。
