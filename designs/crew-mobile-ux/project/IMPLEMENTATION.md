# 手机端 · 单行顶栏 + 侧边栏 · 实现交接

> 面向实现（Android Compose / CrewUi · BoardUi）。本文件只是设计交接，不改产品源码。
> 画布：`designs/crew-mobile-ux/`
> 画板：`Main.dc.html`（聊天首屏）· `Drawer.dc.html`（侧边栏打开）· `Tasks.dc.html`（任务/审批）
> 编辑器：http://127.0.0.1:4720/design/qoSrF9Btc6KNHVP5iaxDGD/

## 一、本批要解决的问题

顶部仍有常驻模式行与成员行，连同连接行 / 会话行 / 更多⋯ 多层堆叠。本批把常驻顶部收成**一行**，把可收起的入口沉到**侧边栏（ModalNavigationDrawer）**。

## 二、顶部结构（唯一常驻行，56dp）

- 全画布口径：安全区 24 + 单行 56 = 80dp（390×844 画布，含安全区假设）。**这是画布目标口径，真机系统栏高度由系统决定，不做假测。**
- 单行从左到右三件，全部命中 ≥48×48dp：
  1. **汉堡 menu**（左，48×48）：打开 `ModalNavigationDrawer`。
  2. **中间：当前会话名，占可用宽**（会话切换，点击开现有会话切换；单行 ellipsis）。**必须能区分所在页**：
     - 聊天页：显示会话名（如 `main`）。
     - 任务页：显示 `任务 · <会话名>`（如 `任务 · main`），单行 ellipsis，切页后仍知道自己在哪。
  3. **右：连接状态，单短词限宽（≤76dp），48 命中**：`●局域网` / `连不上` / `连接中`，点击展开连接详情（复用现有 `CrewConnectionStatus` 语义：`loading` 绝不显绿，`problem` 非空=红「连不上」）。不要挤窄中间会话区。
- **不再常驻**：模式行（聊天/分拣台）、成员「发给」横条、更多「⋯」按钮、独立通知块。它们的功能下沉到 drawer / 输入区 / 消息列表。

## 三、侧边栏（ModalNavigationDrawer，约 300dp）

- 宽 **~300dp**，适配 360dp 宽 OPPO（360 − 遮罩 ≥ 60dp 可见背后页）；**内容可滚动**；**系统 back 关 / 点遮罩关**；右侧圆角 16。
- **分组顺序：上半部常用导航 → 成员 → 工具**，不让侧栏变成 24 项功能堆。
  1. **导航**（drawer 上半部）：
     - `聊天`（当前页时 selected 高亮）
     - `任务 · 分拣台`（带「待处理 N」角标，示例）→ 即 `Tasks` 页/现事务板视图
  2. **成员 · 选收件人**（真实花名册：大哥 / 写手 / 码农）：
     - 行主体 = 选当前收件人；`aria-pressed=true` 标**实际主收件人**（不是导航 selected）。
     - **行尾独立「资料」48dp 按钮**：显式可发现的名片/人设/屏幕入口，**不要只靠长按**。
  3. **工具**（下面）：事务板 / 会话管理 / 模型 / 后台 / 屏幕。
     - 事务板：若「任务」导航已能进入任务视图，事务板入口不再重复堆列表——按真实组件现状接（现有「事务板」是抽屉，`任务`导航可直接复用本 `Tasks` 页，避免两个入口同义重复）。
- **底部**：连接状态一行（可点详情），与主顶栏同一语义。
- **导航 selected ≠ 成员 selected**：
  - 导航项 `selected` = **当前所在页**（聊天 / 任务）。
  - 成员项 `selected`（`aria-pressed`）= **实际主收件人**。二者独立，不混成一个"可选态"。

## 四、收件人（输入区，复用现有 64dp，不新增第二排）

- 输入区是**单行**（64dp），从左到右：
  1. **左侧 48×48 收件人按钮**：圆角 13 小胶囊，视觉直接显示名字 + ⌄（如 `大哥 ⌄`）。名字 **1–3 字单行 ellipsis，按钮最大 64dp**；点击打开 drawer 成员分区选人。
     - 语义「发给」放 **`contentDescription`**（`发给：<名字>，点击选择成员`），**视觉不写"发给"字**，省横向空间。
     - 命中 48×48。
  2. **正文 TextField**：`weight` 吃剩余宽度，360dp 下仍约 180dp 可用，不缩成 5 字；**用户原始 `@` 也在正文里可见**（不把这颗按钮当作 @ 文本的替代）。
  3. **发送**：维持 48×64 尺寸，不扩大。
- **不叠点击层**：收件人按钮与正文输入是行内相邻两块独立命中，收件人按钮 48×48 不覆盖正文编辑区（正文自身命中由 TextField 提供）。**不做"上层 label 48 + 下层 input 48 堆在 56 高"那种几何不成立的叠层。**
- **默认收件人来源**：由后端该会话的 **default 角色**决定，**不硬编码"第一位成员"**。画布示例写 `大哥`（示例）仅示意。
  - ⚠️ **交接前核实真源**：若后端 bots 数据没有 `role` / `default` 字段，不要凭前端猜一个"默认"。请实现方先确认后端会话/成员数据里当前收件人的真源字段；拿不到就按"未指定 → 用后端返回的默认；后端也没给就显示未指定态"，**不造 default**。

## 五、通知

- 不再独立 56dp 常驻块。改为**消息列表内一条可滚动项**，默认**一行摘要**，原生 `<button aria-expanded>` 展开全文（保留历史，不删通知）。

## 六、Tasks（任务/审批页）

- 顶栏同上：menu · `任务 · <会话>` · 连接。
- 无模式行、无更多⋯（分拣台就是本页，从 drawer 进来）。
- 顺序：**待你处理 → 进行中 → 办完（默认折叠一行）**。
- 审批两阶段（勿混为"HTTP 已受理=已处理"）：
  - **submitting**：按钮「提交中…」禁用，同题禁双点，其余项同时禁用。
  - **accepted**：后端已受理、等工单状态更新，副标「答复已受理，等待状态更新 · 同一题不可重复点击」。
  - 到最终态才解除并更新卡片。画板只示意中间态，示例数据。

## 八、实现注意

- 静态画板，**无假 onClick**：交互语义用原生 `<button>/<input>/<label>/aria-*` 表达，落地用真实 Compose 控件。
- 顶部三件、drawer 导航项、成员行、资料按钮、输入区收件人 label、发送、折叠行：**命中全部 ≥48×48dp**。
- 强不**编造在线/当前任务数据**：画板里所有数字/状态标「示例」，不声称运行实态。
- 系统状态栏/安全区由系统绘制，画板只留空白占位，不虚构 9:41/信号/电量。
- 不删除历史、不恢复归档功能；沿用现有 session 唯一真源、`Recipient` / `ApprovalGate` 语义与连接组件，不重写协议/后端。
- 不改 Mac 焦点、不抢桌面输入。

## 九、画布目标口径（仅画布，不是真机实测）

- 顶部应用控制区：56dp/行（+安全区 24 画布假设）≈ 画布 390×844 的 ~9.5%（含安全区）。
- 消息/任务区：显著扩大（当前画布顶部仅 56dp 单段）。
- 分隔：**画布目标 vs 真机实测**不混用；真机通过前不标"已验证"。
