# Personal Agent 设计系统

从九张画板的渲染结果里抽出来的可复用刻度。机器可读版本在 `tokens.json`。

数值来自 `getComputedStyle` 实测，不是从源码猜的 —— 源码写 `width: 300px` 的地方，实际渲染是 329px。

## 气质

暖白底、低饱和、靠留白和层次说话，不靠边框和色块。稿子源码里的注释原话如此。

唯一的暖色破局点是语义色：「等你决定」赭、失败红。它们不做装饰，只做状态。

## 五、结构要点

看过画板才明白的几件事：

1. **子代理卡在消息流里，不在右栏。** 它回答的是「这段话派下去谁在跑」，和右栏的工单是两件事。表头「N 个子代理 / x 在跑 · y 已完成」+ 分隔 + 每行一个分身 + 脚注。
2. **左栏每项有 5px 状态点**：在跑绿 / 等你赭 / 失败红 / 其余灰。
3. **代码块有逐行 +/- 高亮**：新增行绿底，删除行橙底。
4. **右栏三个页签**：进行中 / 待你 / 已完成。
5. **消息贴底**（手机）：空白留在上方，视觉重心落在输入框附近。

### 两处「宁可空着也不造假」

1. **工单进度条不画**：后端只给已发生的经过（`steps`），没有计划里的总步数。
   拿「读到几步」当分母，进度条会永远停在 100%，那比不画更糟。
   `progressOf` 要求 `TotalSteps > 0` 才画；`stepOf` 退化成只说「第 N 步」。
2. ~~**消息结果条不画**~~：产出接口已经接上（`GET /api/mobile/outputs`，见 `docs/00-contract.md` §5.4）。
   现在只有在**这条消息带 `ticket_ref`、且那张票确实交出了文件**时才画；三件事一律不画：
   没有票号、`empty`、`unavailable`。读不到不写成「没有」，这是这一栏唯一的分寸。
3. **未读徽标只在算得出来时画**：数的是「人发出去、队伍还没被读走」的条数，来源是网关队列
   已有的 `messages.read_at`（见契约 §5.6）。网关不报这一列时 `state` 是 `unknown`、`count` 是
   `null`，此时**不画** —— 画成 0 等于说队伍把话都读过了。「队伍说了你还没看」那一条没有
   阅读回执，这一版不编，缺的那一半写在契约 §5.6 末尾。

### 主题覆盖

`CREW_THEME=light|dark` 只给拍照对照用：验亮色本来得把系统切成亮色，
而那属于改用户的工作环境。不设时依旧跟随系统。
