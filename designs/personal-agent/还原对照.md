## 第四轮：字重、刻度收敛、两个诚实的决定

### 字重全部按画板改准

画板用的是 640 / 620 / 600 / 550 这些非整数档，我原来全用 `Bold()`（700），整体偏重。
现在 `ui.go` 里只剩 4 处 `Bold()`（配对区，画板没有那处），其余都走 `WeightTitle=640`、
`WeightFigure=620`、`WeightName=600`、`WeightCard=550`、`WeightLabel=600`。

### 裸数字清零

`ui.go` 里 `.FontSize(13)` 这种手写值从 9 处降到 0，全部走刻度常量。
检查器加了这条规则，并且修了它自己的漏报（多行书写时 `.FontSize(` 在行首，旧正则抓不到）。

### 检查器新增「定义了必须用」规则

圆角与字重常量定义了却没用到 → 报错。这条规则一上来就抓出 7 个空定义，
其中 **`RadiusCard` 写的是 9，画板实测是 10** —— 是个真错，已改。

字号不受这条约束：字号要齐全（对得上设计稿），但不必每个都用上。

### 两个「宁可空着也不作假」的决定

1. **进度条不画。** 画板里工单卡有「第 2 步 / 共 3 步」的进度条，但后端只记录已发生的
   经过（`steps`），没有计划里的总步数。拿「读到几步」当分母，进度条会永远停在 100% ——
   那比不画更糟。`progressOf` 现在要求 `TotalSteps > 0` 才画，否则返回 (0,0)。
   `Task` 里留了 `total_steps` 字段，后端给了就能画。
2. **「看它的屏幕」不装死。** 画板里有这个按钮（109×31 圆角 9），我把它画出来了，
   但后端没有截浏览器画面的接口。按下去会说「还看不到它的屏幕：这一步还没接上」，
   而不是没反应。`screenReady` 为 false 时文字用更淡的 Hint 色。

### 顺手补齐的

底部导航从 2 项补到 4 项（后台 / 模型 / 产出 / 常规任务），徽标加了强调淡底和 6px 圆角；
输入区改成 13px 圆角白底带边；状态点从字形 `●` 改成真正的 5px 方块（字形大小跟字号走，
控制不住）。

## 第七轮：后台页与一个类型陷阱

后台页加了「进行中 / 待你 / 已完成」三档，按画板的右栏补齐。

### 抓到一个静默 bug

第一版「进行中」**整栏是空的**，但后端明明给着一张在跑的工单。

原因：`needsPerson` 在 Kotlin 里是 `String` 而不是 `String?` —— 后端没给这个字段时
`optString` 返回空串。我按 `needsPerson == null` 写分桶，这个条件永远不成立，
于是所有工单都被「进行中」排除掉。

**编译通过、不报错、不崩**，只是一整屏内容不见了。这种 bug 只有看画面才能发现。

写进 `TicketTabTest.kt` 四条测试钉住，并且**验证过它真能抓**：把实现改回
`needsPerson == null || isEmpty()`，三条测试立刻失败。

## 第八轮：桌面端第一次看见真实画面

用户开了屏幕，`displays` 从 0 变 2，ScreenCaptureKit 恢复。

### 看到的第一个画面是灾难

竖排文字：「对话」「看它的屏幕」「跟」全部一字一行地竖着排。三栏挤在左上角。

**两个根因，都是「不写就默认」的坑：**

1. `ui.Scroll(c).Grow(1)` 没配 `FillWidth()` —— 宽度由内容决定，中文被压成一字一行
2. `conversationPane` 的 `Column` 只有 `Grow(1)` 没有 `FillWidth()` —— 同上
3. 窗口 880×620，但三栏需要 329+718+393=1440 —— 横向根本放不下

### 然后数据不出现

修好布局后，界面写着「队伍还是空的」「正在读对话…」，但 `curl` 返回 200。

**根因：`arrived` / `failed` 等通道从未 `make`。** `&app{client: ...}` 只设了 client，
其余字段是零值 —— nil 通道上的发送会**永久阻塞**。刷新协程把数据送到 `s.arrived` 那一行
就挂住了，而主线程的 `drain` 永远收不到。

这个 bug 的特征值得记住：**编译过、go vet 过、测试过、不报错、不崩溃**，
只是界面永远停在「正在读…」。跟 Android 那个 `needsPerson == null` 是同一类。

修法：把通道初始化收进 `newApp(client)`，并加 `wiring_test.go` 钉住。
验证过能抓：删掉 `arrived: make(...)`，测试立刻报
`arrived 是 nil：刷新拿到的对话永远送不到界面`。

## 截图方式：只按窗口 ID 抓，不动窗口

用户两次叫停：「能不能不要一直抢前台频繁启停，你直接抓窗口截图不行吗」「你又在关他干什么啊」。

他说得对。反复重启窗口、把它抢到前台，看图的人会一直被打断 —— 这是**我为了省事，把成本转给了他**。

现在 `scripts/shot.sh`：
- 走 `SCScreenshotManager.captureImage`，按窗口 ID 单张抓，不启动流
- 不抢前台、不挪窗口、不重启进程，窗口被挡住也能抓
- **进程没开时不会自动去开** —— 开窗口是人的事

### 试过但走不通的两条路

为了让程序截自己（彻底不碰窗口），试了 `NSView.cacheDisplayInRect` 和 `CALayer.renderInContext`。
两条路抓出来**都是空白**：文件 88KB（纯色）而不是 213KB。

原因：mygo 用 Metal 直接画，不走 AppKit 的 drawRect，也不往 CALayer 里缓存。
`renderInContext` 只重放 layer 树，Metal 的 drawable 不在里面。

**留了个判据**：截图字节数。88KB 就是空白，200KB+ 才有内容。这个数字比肉眼看图快。

### 走通的方案为什么之前报 -3811

`SCStream`（持续流）在多显示器 + 1440 宽窗口下会报 `-3811 音频/视频捕捉失败`；
`SCScreenshotManager.captureImage`（单张）不走那条路径，一直成功。
