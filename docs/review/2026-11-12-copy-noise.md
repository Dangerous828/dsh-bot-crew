# 增补发现：界面解释性文案过多

- 日期：2026-11-12 18:03
- 来源：操作者看真机截图后提出，非四份评审中的任何一份
- **四份评审都漏了这一条**：`ui.md` 抓的是对比度/字号/触控/空态密度，`ux.md` 抓的是流程，都没抓「常驻解释文字」这个系统性噪音

---

## 一、判断

**直觉对，但「解释太多」是表象。**

真正的问题是：**把「不编造」这条工程纪律，从行为层错误地延伸到了文案层。**

| | 行为层（对，之前评审称赞过） | 文案层（错，本条要修） |
|---|---|---|
| 做法 | 该不画就不画；读不到就说读不到；没做就别做成能用的形状 | 不断补一句解释，来证明自己没骗人 |
| 例子 | `unknown` 不画进度条、`empty`/`unavailable` 分开、没有改动就没有「采用」按钮 | 「忘掉的条目不删，只是不再进它下一次开口时的上下文」 |

> **诚实 ≠ 把机制念给用户听。诚实的界面用状态表达，不用文字解释状态。**

截图里那三处红框，全是「界面已经表达了、又用文字解释一遍」或「把后端怎么存的直接念出来」。

---

## 二、三处分别怎么处理（不能一刀切）

| # | 文案 | 位置 | 性质 | 处理 |
|---|---|---|---|---|
| 1 | 「和大哥说话」 | `desktop/ui.go:1310-1321` `subtitle()` | **冗余** | **删**。左边已有头像「大」+ 名字「大哥」 |
| 2 | 「忘掉的条目不删，只是不再进它下一次开口时的上下文。」 | `desktop/ui.go:3304` 常量 `memoryNote`，钉在 `:3300` | **内部机制泄漏** | **删常驻**。改成按钮措辞「不再记住」+ 点完短暂回执「已忘掉 · 撤销」；机制说明收进帮助层 |
| 3 | 「都在待命，发出去就会接上」 | `desktop/ui.go:2515-2527` `statusLine()` | **有价值** | **留**，但改位置：与错误行合并成一条状态带，用颜色/图标区分常态与错误 |

**第 3 条最容易被误删**：它回答的是「我现在发消息会怎样」这个真实的临门一脚疑问，删了反而更差。它的问题是**和另外两行挤在一起**，不是它本身多余。

### 关于第 1 条，代码自己已经反对过自己

`ui.go:1977-1979` 的注释：

> 画板的 Bot 发言只有「头像 + 正文」，没有名字行也没有角色行 —— **头像本身已经说明了是谁**。连续几段同一个人发言时，再加名字会把消息流读成一连串带标题的段落，Rhythm 就散了。

这条理由完全适用于顶部副标题。同一份代码里，消息流遵守了，页头没遵守。

### 关于第 2 条，「必须说」这个判断本身是错的

`ui.go:3295` 注释：「脚注钉在列表下面：它说的不是某一条，是整本账的性质」；`:3303`：「这一栏**必须说**的那句实话」。

但 `memoryPane` 开头（`:3250-3254`）那套「如实说」纪律，约束的是 **empty / unavailable / 读失败** 这类**异常态**。把它扩展成「任何时候都要主动交代存储实现」，是纪律越界。用户没问，界面不必自证。

> **改的时候注意**：`memoryNote` 一名两用 —— `ui.go:206` 的字段 `s.memoryNote` 存的是「读不到时的原因」（`:3212`、`:3264-3265` 在用，这个**该留**），`:3304` 的常量 `memoryNote` 是常驻脚注（**该删**）。同名不同义，别一起删掉。

## 三、顺带发现：两条比「解释多」更该修的

### 3.1 英文原始错误漏到界面（P1）

截图里 `播报没成功：text is required`。

- `desktop/ui_speak.go:22,26` → `note: "播报没成功：" + err.Error()`
- `desktop/ui_voice.go:62` → `note: "没识别成功：" + err.Error()`
- 渲染在 `ui.go:2420` 一带

`err.Error()` 直接拼上界面。**这一条推翻了 `ux.md` 的一条正面结论**：那里称赞「`ok` 必须来自后端真字段，否则原样显示 `reason`」——`reason` 是中文人话时成立，是后端英文内部错误时就翻车。

**改**：桌面侧加一层错误映射表，把已知内部错误翻成中文人话；未知错误给通用的「这次没成功，稍后再试」，把原文收进日志或可展开的详情。

### 3.2 「听播报」逐条重复（P2）

`ui.go:1980` 每条 Bot 回复下面都挂一个，截图里连着出现 5 次。行动标签逐条重复，把消息流切成一段一段。

**改**：悬停/选中该条时才出现，或收进消息右上角的 `…`。参考 `ui.go:1977` 注释里已经有的「别把消息流读成一连串带标题的段落」这条判断。

## 四、一个必须定的产品决策

**这套界面是「给开发者本人用的调试面板」还是「给使用者用的产品」？**

`business.md` §3 判它是「多 agent 任务的远程遥控器」，用户是操作者本人。按这个定位，开发者确实可能想知道「忘掉到底删没删」——**这些解释在自用场景里有合理性**。

但**有合理性 ≠ 该常驻主界面**：

| 定位 | 处理 |
|---|---|
| 自用 / 开发者工具（当前） | 机制解释收进「详情 / 帮助 / 首次可关闭提示」，主界面只留状态与动作 |
| 给别人的产品 | 全部改成用户语言，机制说明不进界面 |

**两种定位下，第 1、2 条都该从主界面拿掉** —— 区别只是「挪到哪」，不是「留不留」。所以这一条**不需要等决策就能动手**。

## 六、补查：与设计稿的关系（18:10 复核）

操作者接着问「UI 和之前的 claude design 差很多吧」。核了 `designs/personal-agent/` 九张 `.dc.html` 画板与 `还原对照.md` 后，结论要修正一下：

**骨架没差。** `还原对照.md` 记录了四轮逐块对齐：字号刻度、`Radius*` 刻度、三栏实测宽 329/718/393、字重收敛、`ui.go` 裸数字清零、气泡右下 4px 尖角。`README.md` 的「稿子与代码的对照」表几乎全标「已实现」。

**差在两处：**

1. **标题栏的信息层被换掉了。** 设计稿 `project/Desktop-dark.dc.html:101` 主标题是「林 · 前端」（名字 + 职能），`:104` 副标题是「正在工作 · 3 分钟」（实时状态 + 时长）；实现 `ui.go:1323` `title()` 只有名字、`ui.go:1310-1321` `subtitle()` 是「和大哥说话」。**所以 §二 第 1 条不只是「多了一句解释」，是把有信息的状态行换成了零信息的身份重复。** 修复方向也随之改：不是单纯删掉，而是恢复「名字 · 职能」+「实时状态 · 时长」。
2. **后半程新增的面板没有画板。** `canvas.json` 九张里，右栏只画了「后台」，左栏导航只有 4 项（`Desktop-dark.dc.html:76-91`：后台/模型/产出/常规任务），**没有「记忆」**。真机截图里那个「记忆」右栏（一条记忆 + 机制解释 + 配对 + 设备列表 + 导出备份 + 队列 + 全部暂停）没有任何画板定义过。模型/产出/常规任务/记忆四个面板都是「无稿实现」—— 这正是「解释性文案自己长出来」的根因，§一 的判断因此有了出处。

**一个必须澄清的误判**：真机中栏看起来空、卡片少，**不是 UI 退化**。`render/对照-设计稿vs实现.png` 是 `tools/design-mock.py` 把画板文字原样喂给桌面端做的对照，那时代码卡、采用按钮、结果条、子代理卡全都画得出来。真机空是真实数据没触发，而契约明确要求「没有改动就没有『采用』按钮」「`empty` 不画假条目」。**如实不画是正确行为**，别改成常驻假卡片。
