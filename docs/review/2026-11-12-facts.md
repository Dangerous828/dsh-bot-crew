### 2.1 这一节最要紧的一句

**F-01 是唯一一条「文档说没做、代码已做」的硬伤**：`docs/00-contract.md:173` 把手机端进度条写成未来四步计划，而 `CrewWire.kt` + `CrewUi.kt` 已经实现并有自己的注释解释口径。任何按契约做评审的人都会把「已完成」记成「未做」，进而给出错的优先级。

**F-04 是第二硬的一条**：`steer` 已通，契约仍说「没有往 worker 敲字的通道」。它比 F-01 轻，因为严格说「终端 stdin」确实没有；但对外表述会低估已有能力。

**F-02 / F-03 / F-05 / F-06 / F-07 是正面样本**：文档对「没做」的部分说得准，且错误码、空态话术、`empty` vs `unavailable` 的区分都能在代码里逐条对上。这套「如实说没接上」的纪律在整个仓库里是一致的。

### 5.3 三条外网通路（业务评审必须知道的约束）

`docs/06-relay.md` + `04-verified.md`：局域网直连 / 自建 relay 中转 / 兜底。已知硬约束：

1. 后端**必须绑具体地址**，`0.0.0.0` 被 DSH 明确拒绝（「binding every interface would expose remote code execution to the network」）。
2. 管理 API 从局域网访问 **403**（`sameOrigin` 只认 `127.0.0.1:<port>` 的 Host），手机面不受此限。
3. Android 模拟器曾有「连不上」的错误结论，实为连接页填完整 URL 时 URL 端口优先于 Port 字段 —— 已澄清，不是缺陷。

## 7. 给三份评审的三句话

1. **别把「已完成」当「未做」**：F-01（手机进度条）、F-04（steer 已通）是契约里的两处过期表述，代码比文档新。
2. **「没做」的部分文档说得准**：`routines` 无写接口、`screen` 无画面源、`takeover` 只停票 —— 这三条别再当缺陷提，它们是**已经声明过的边界**。
3. **最薄的地方是 `relay`**：1,470 行只有 6 个 spec，而它是外网唯一入口；`main.go`/`pair.go` 无单测，启动与配对路径裸奔。
