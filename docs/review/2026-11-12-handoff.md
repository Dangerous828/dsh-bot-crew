## 一、先看这个：三件不能做错的事

### 1. 别重做已实现的（最贵的一件）

**如果按 `docs/00-contract.md` 派活，会重做四样东西。四样都已经写完了。**

| 「采用」按钮还没接 | `:257-260` | `CrewUi.kt:2344-2468` 完整状态机（`adopting`/`adopted`/防重复点/失败话术分离） |
| 没有往 worker 递话的通道 | `:351` | `POST /api/mobile/steer` 已通，**插队 + 认领两条语义**（`mobile-http.ts:583-614`） |

**为什么这条排第一**：重做 `steer` 的插队/认领语义，**未必能重做对**。那两条路（`:596-614`）是踩过坑写出来的。

**动作**：改契约四处。改写文本在 `docs/review/2026-11-12-business.md` §2，直接抄。

---

### 2. `resume` 缺失 —— 这是产品前提的洞

**现状**：

- `pause` 已实现，`scope: 'executor'`（`mobile-http.ts:653-663`）
- **恢复只能在桌面**

**场景**：手机按了暂停 → 人在外面 → **票是死的**。

这不是功能缺失。如果这产品是「远程遥控器」，**遥控器上必须有「继续」**。没有就不是遥控器。

**动作**（10 行路由 + 一个按钮态）：

```ts
// backend/src/app/mobile-http.ts，紧挨 pause 注册
POST /api/mobile/resume  →  settings.pause(false, 'panel')
```

不要新增契约 —— `scope` 字段已经预留口子，只是这一半没接。

---

### 3. 175 个测试 ≠ 能用

**实测**：`go test ./...` → **175 pass / 1 skip / 0 fail**，1.1s。

**但这 175 个测的是布局函数和点击命中**（`uiClick_test.go`），不是「用户点下去有没有反应」。

`TestAgainstTheLiveGateway` 按设计 `t.Skip` —— 这是「未做联调」的机器可读证据。

**动作**：见 §三 验收。在此之前，**没有任何一条「能用」的结论成立**。

## 六、评审边界（别越过）

1. **本轮零真机**：没启动过窗口、没连过设备、没跑过浏览器
2. **后端未跑**：`backend/` 的 642 个 TS 用例本轮**未执行**，只做了静态阅读
3. **对比度是实算的**，但**渲染效果未验** —— 色值对不代表屏幕上好看
4. **ux 报告的配对/派活/记忆三段无证据**，其结论不采信
5. **`docs/04-verified.md` 的 1213 个宿主测试未复跑** —— 那是另一个仓库

**结论强度上限**：本评审能证明「代码写得对、文档写得旧」，**不能证明「产品能用」**。
