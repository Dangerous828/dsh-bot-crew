# 隧道协议

宿主与中转之间走的是 **WebSocket 上的二进制帧**。线格式的事实源是
`backend/src/app/relay-protocol.ts`（`relay/src/relay-protocol.ts` 是它的拷贝，由
`relay/sync-protocol.sh` 同步，`relay/tests/parity.spec.ts` 逐字节比这两份）。

## 一帧长什么样

```
+--------+----------+----------+-----------------+
| type   | id       | length   | payload         |
| 1 byte | 4 bytes  | 4 bytes  | length bytes    |
|        | big-end | big-end  |                 |
+--------+----------+----------+-----------------+
```

- 一个 WS binary 消息里可以有**多帧**，一帧也可以跨多个消息 —— 解码器按字节流拼，
  读够一帧交一帧（`frameDecoder`）。这是为了防「一次 send 被 TCP 分片」。
- **length 按字节算，不按字符**。「中」是 1 个字符、3 个字节。按字符写长度的实现会让对端
  一直等一个永远凑不满的帧，症状是所有中文请求卡死。
- 单帧上限 64 MiB（解码器与两端都可配）。超了当场废掉连接，**不是**先攒下来再判 ——
  一个声称 4 GB 的帧头是公网暴露面上最省事的「吃掉你内存」的办法。
- 控制帧的 payload 是 UTF-8 JSON；数据帧的 payload 是原始字节，**不 base64**。

## 帧类型

| 编号 | 名字 | 方向 | payload | 说明 |
| --- | --- | --- | --- | --- |
| 0x01 | register | 宿主→中转 | JSON `{instanceId, name?, secret?}` | 连上之后第一条。之前发别的都是协议错误 |
| 0x02 | registered | 中转→宿主 | JSON `{}` | 注册成功。宿主拿它当「可以接请求了」 |
| 0x03 | updatePairing | — | — | 保留编号，本实现不发也不读 |
| 0x04 | httpRequest | 中转→宿主 | JSON `{method, path, headers}` | body 随后以 httpBody 流式发 |
| 0x05 | httpBody | 中转→宿主 | 原始字节 | **空 payload = body 结束** |
| 0x06 | httpHead | 宿主→中转 | JSON `{status, headers}` | |
| 0x07 | httpChunk | 宿主→中转 | 原始字节 | |
| 0x08 | httpEnd | 宿主→中转 | 空 | |
| 0x09 | httpError | 宿主→中转 | JSON `{message}` | 上游出错。文字不转发给手机 |
| 0x0A–0x0F | wsUpgrade…wsClose | — | — | WebSocket 隧道。**本实现不支持**，收到就丢 |
| 0x10 | ping | 两端 | 空 | 15s 一拍 |
| 0x11 | pong | 两端 | 空 | 45s（宿主）/ 60s（中转）收不到就判死 |
| 0x12–0x1B | pairRequest…pushSend | — | — | 参考实现有，本实现不参与 |
| 0x14 | httpCancel | 中转→宿主 | 空 | 手机放弃了，宿主应当停掉上游的活 |
| 0x1C | migrate | — | — | 「这台搬家了」。本实现不参与 |

`type` 是全表，不是本实现支持的子集 —— 编号不能自己改。改编号会让「插件包里的客户端」与
「本仓的中转」用不同的字节讲同一件事，而发现这件事的总是线上。

## 一次 HTTP 请求

```
手机            中转                       宿主
 │ GET /i/box/api/mobile/timeline
 ├──────────────►│
 │               │ httpRequest id=1 {method:'GET', path:'/api/mobile/timeline', headers:{...}}
 │               ├─────────────────────────►
 │               │ httpBody id=1 (空)
 │               ├─────────────────────────►
 │               │                          │ forward() 到手，开始跑
 │               │ httpHead id=1 {status:200, headers:{...}}
 │               │◄─────────────────────────┤
 │  200 + 头      │                          │
 │◄──────────────┤ httpChunk id=1 <字节>    │
 │  第一块       ├◄─────────────────────────┤
 │◄──────────────┤ httpChunk id=1 <字节>    │
 │               ├◄─────────────────────────┤
 │               │ httpEnd id=1             │
 │               ├◄─────────────────────────┤
 │  结束         │                          │
 │◄──────────────┤
```

要点：

- **headers 原样转发**，去掉逐跳头（`connection`、`transfer-encoding`、`content-length` 等）。
  设备凭据（`x-crew-device` / `x-crew-credential`）在中转看来只是两个普通头，它不读也不改 ——
  凭据摘要只在宿主手里，中转没法验，也不该验。
- **body 分 64 KiB 一片**发。中转那边先读完整个 body、按上限判过再发 —— 超限的请求
  连一个字节都不会到宿主。
- **响应是流式的**：`httpHead` 一到就写回状态与头，`httpChunk` 一到就写块。
  中转不攒齐再发，否则长流（SSE、大列表）会表现为「点了没反应，几秒后突然全出来」。
- **头到了之后就不再计超时**。头之前的等待有上限（默认 120s），来了之后就是流，慢是正常的。

## 取消

手机断开 → 中转发 `httpCancel` → 宿主 `forward` 收到的 `AbortSignal` 被推倒。

不传这一条的话，一个「手机已经不要了」的请求会在宿主那边一直跑完 —— 长任务会把它拖住。

## 心跳与判死

```
宿主                              中转
 │ ── ping ──────────────────────► │  (每 15s)
 │ ◄──────────────── pong ─────────│
 │                                 │
 │ 45s 没收到 pong                 │ 60s 没收到 pong
 │ → 自己断开去重连                 │ → terminate 这条隧道
```

两边都判死，且**宿主判得更早**（45s vs 60s）。反过来（只靠中转踢）的话，宿主在这段时间里
仍然显示「已连接」，而手机每一个请求都要等中转的超时才见到失败。

## 注册

```
宿主 → 中转：register {instanceId, name?, secret?}
中转 → 宿主：registered {}      ← 成功
中转 → 宿主：wsError {code, message} + close  ← 被拒
```

- `instanceId` 必须匹配 `[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`。它进 URL 路径、路由表与日志，
  带 `/` 或空白的 id 能让路由二义。
- `secret` 走**帧**，不走 URL。URL 会进反代的 access log，而日志里出现一次密钥就等于泄露。
  也接受握手时的 `Authorization: Bearer <secret>`，方便只配头不配帧的写法。
- **同一个 instanceId 的两条连接**：配了密钥时，出示同一把密钥的新连接**接管**旧的那条
  （断网重连时旧连接常常还挂在服务端，TCP 半开）；没配密钥时后到的被拒 —— 没有身份可言，
  让它接管等于任何人都能把别人顶掉。
- 连上之后 **10 秒内不注册就断开**：公网上最便宜的攻击是「连上然后什么都不说」。

## 设备凭据

中转**验不了**设备凭据（设备表在宿主的磁盘上）。它做的是另一件事：看宿主怎么回答。

宿主的回答是 401/403 → 中转在这个来源地址名下记一次失败 → 超过阈值（默认 20 次/分钟）
就封 60 秒，期间直接 429，不去打扰宿主。

这条闸拦的是**暴力尝试**，不是「没配对的人」—— 后者本来就进不去，因为宿主会 401。
